### <a name="_qmphm5d6rvi3"></a>**Решение**

[Диаграмма контекста](Credit%20process%20context%20diagram.png)

[Диаграмма контейнеров](Credit%20process%20container%20diagram.png)

**Архитектурное решение:**

1. **Сайт — подача заявки новым клиентом:**
   - Сайт загружает условия кредитов из Кредитного конвейера через API
   - При подаче заявки с паспортными данными выполняется предодобренный скоринг
   - Предодобренный скоринг: Сайт → Скоринг-сервис → БКИ (только общие данные)

2. **Интернет-банк — подача заявки действующим клиентом:**
   - Клиент видит условия кредитов и предодобренные предложения
   - Заявка подтверждается СМС-кодом
   - Заявка передаётся в Кредитный конвейер через Kafka
   - Кредитный конвейер запускает полный скоринг (асинхронно)
   - Статусы заявки передаются обратно в интернет-банк

3. **Синхронизация с АБС:**
   - Ежесуточная загрузка заявок из АБС в Кредитный конвейер (+R9)
   - Асинхронная публикация событий об изменении статусов через Kafka

### Логика принятия решений и выбора технологий

1. **Использование Kafka** (+R4, +R5):
   - Уже используется в Task3 для депозитов
   - Обеспечивает асинхронную интеграцию между Интернет-банком, Кредитным конвейером и АБС
   - Позволяет масштабировать потребителей независимо

2. **Предодобренный скоринг на сайте:**
   - Выполняется через Сервис скоринга с использованием только общих данных БКИ (+R7)
   - Позволяет дать клиенту быстрый ответ без полной проверки
   - Ограничение: только для новых клиентов без идентификации

3. **Полный скоринг через Кредитный конвейер:**
   - Для действующих клиентов — полный скоринг с данными из АБС и БКИ
   - Асинхронный (+R7): запрос ставится в очередь, обрабатывается по возможности
   - Срок — в течение одного дня

4. **API для получения условий кредитов:**
   - Сайт и Интернет-банк запрашивают условия из Кредитного конвейера (+R6)
   - Кэширование условий для быстрого отклика (P1)

5. **Синхронизация с АБС:**
   - Ежесуточная выгрузка заявок из АБС в Кредитный конвейер (+R9)
   - АБС-адаптер публикует события изменений в Kafka

6. **Масштабирование:**
   - Интернет-банк, Сайт, Кредитный конвейер — горизонтально (+R8)
   - АБС — только вертикально (+R2)

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. **Прямая интеграция сайта с АБС**
   - Сайт напрямую вызывает АБС для сохранения заявки
   - *Недостаток*: нарушение принципа асинхронной интеграции (+R5), прямая нагрузка на АБС

2. **Единый API-шлюз для кредитов**
   - Создание отдельного API-шлюза для кредитных продуктов
   - *Недостаток*: дополнительный компонент, усложнение архитектуры на текущем этапе

3. **Синхронный скоринг в реальном времени**
   - Клиент ждёт результата скоринга при подаче заявки
   - *Недостаток*: плохой UX при долгом ожидании, высокая нагрузка на БКИ

4. **Хранение условий кредитов на сайте**
   - Кэширование условий в БД сайта
   - *Недостаток*: рассинхронизация с Кредитным конвейером (+R6), дублирование данных

**Недостатки, ограничения, риски**

1. **Двухэтапный процесс для новых клиентов**: клиент подаёт заявку на сайте, но должен прийти в отделение для идентификации (+R1). Может привести к потерям на воронке.

2. **Зависимость от БКИ**: при недоступности БКИ предодобренный скоринг невозможен, клиенты не получают быстрый ответ.

3. **Асинхронный скоринг**: клиент не получает решение моментально, необходимо уведомление через СМС.

4. **Ежесуточная синхронизация с АБС**: задержка данных в Кредитном конвейере, возможны расхождения.

5. **Вертикальное масштабирование АБС**: ограничение по производительности АБС (+R2), возможное узкое место при росте нагрузки.

6. **Сложность интеграции**: несколько систем (Сайт, Интернет-банк, АБС, Кредитный конвейер, Скоринг, БКИ) должны работать согласованно.

7. **Риск рассинхронизации статусов**: при асинхронной передаче статусов через Kafka возможны задержки отображения статуса для клиента.

8. **Безопасность паспортных данных**: передача паспортных данных с сайта требует дополнительного шифрования и compliance.
